# research — бэктесты, walk-forward и поиск эджа

Конвейер проверяет нашу же стратегию (та же `strategy.check_signal`, те же
риск-правила) на исторических данных Bybit и ищет, есть ли вообще эдж при
реальных издержках.

## Запуск

```bash
./venv/bin/python research/data.py 7 --refresh   # скачать/обновить кэш 1m (7 дней, 15 символов)
./venv/bin/python research/run_all.py            # полный цикл: бэктест + walk-forward + edge-scan + report.md
```

## Состав

| файл | что делает |
|---|---|
| `data.py` | загрузка 1m-свечей Bybit v5 с кэшем в `cache/`; агрегация в 5m |
| `backtest.py` | событийный бэктест: пост-онли вход с буфером, SL/TP, безубыток, тайм-стоп, комиссии, дневной стоп-аут |
| `indicators_vec.py` | векторные ATR/RSI/BB/EMA — быстрая предфильтрация баров перед точным `check_signal` |
| `walkforward.py` | подбор параметров на прошлом, проверка на будущем (OOS), без подглядывания |
| `edge_scan.py` | логистическая регрессия (numpy) на признаках входа + бакет-анализ (час, ATR, объём, сторона) |
| `run_all.py` | всё вместе + `results/report.md` |

## Модель исполнения (консервативная)

- вход: postOnly по open следующего бара с буфером 3 бп; вход только если бар
  реально прошёл эту цену (эмуляция отказов пост-онли и спреда);
- SL/TP в одном баре → считаем SL первым;
- SL/тайм-стоп → taker-fee (5.5 бп), TP → maker (2 бп).

Отдельно издержки считаются в отчёте: цена круга ≈ 10.5 бп цены, и именно
отношение «издержки / размер стопа» задаёт требуемый винрейт.

## Главные находки (2026-11, ~7.6 дней, 15 символов)

1. Текущий конфиг: винрейт 19.9% при требуемых 28.6% (RR 2.5) ещё до комиссий.
2. Комиссии съедают ~0.28R на сделку (315 USDT с депо 1000 за 7.6 дней).
3. Walk-forward выбирает более широкие стопы (SL 3.5×ATR): OOS лучше базового,
   но всё ещё отрицательный — чистой подкруткой параметров эдж не находится.
4. Признаки входа (RSI, ATR, объём, дистанция до BB) не предсказывают исход
   (OOS AUC ~0.30); лонги заметно хуже шортов.
